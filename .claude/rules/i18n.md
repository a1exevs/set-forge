# Interface Language (i18n)

Every interface text comes from a dictionary in the language the user chose on the device; the build fails when a
key is missing in a language, unused, or when a text is written into a component.

## The language

- One source: the language store of `client/src/shared/lib/i18n` — detected once on the first open (session
  invariant `interface-language`), persisted on the device, written to `<html lang>`, followed by i18next.
- The supported languages are the list `LANGUAGES` there, each named in itself. A new language is a dictionary in
  `client/src/app/i18n` plus an entry in the list; the dictionary checks, the language control and the Storybook
  toolbar pick it up, and `Record<Language, …>` (the legal documents) does not compile until it has its content.
- The language is a device preference, not account data: it never goes to the server.

## Dictionaries and keys

- `client/src/app/i18n/en.json` is the reference; `dictionaries.ts` types every other dictionary by its shape and every
  `t('…')` key by its keys — a typo or a missing key fails `tsc`.
- Keys are nested by where the text lives: `<slice>.<name>` (`settings.title`, `profile.openSettings`); words shared by
  several screens go under `common` (`common.back`).
- Keys are static strings: the checks read the code, so `t(\`errors.${code}\`)` would be invisible to them. Plurals
  and values go through i18next options (`t('key', { count })`): a plural key has the forms of each language
  (`_one` / `_other`; Russian `_one` / `_few` / `_many` / `_other`), and a number that is no plural is not named
  `count` — `count` makes i18next and the checks look for plural forms.
- Dates follow the language too: `formatDate(iso, language)` of `@shared/lib` (Intl) with the `language` of `useT()`,
  never a fixed locale.

## Texts in components

- A logic layer calls `const { t } = useT()` and passes `t: Translate` to its presentation; a presentation never calls
  the hook (component-architecture). A presentation-only component that needs text gets a logic layer for it.
- `shared/ui` is domain-agnostic: it takes ready strings as props (`ariaLabel`, `label`, `title`) and never `t`. A
  text prop has no default — the caller names it, so `shared/ui` holds no text of its own in any language.
- Nested components of one file take `t` or an already translated string; passing `t` deeper than that means the
  piece deserves its own component with a logic layer.
- A toast is given `t(…)`, never a literal.
- A sentence with a link or other markup inside is one key with tags (`… the <policy>Privacy Policy</policy>`),
  rendered by `Trans` of `@shared/lib` with `t`, `i18nKey` and `components` — never glued from several keys, so every
  language keeps its own word order.
- An error kept on screen is kept as a code or as the error itself, and its text is built at render: it follows a
  language switch like the rest of the screen. A model's validator returns a code, never text.
- Language names in a control are shown in their own language and carry it (`lang`) for screen readers.

## Tests and stories

- A presentation spec passes the English `t` of `client/tests/common/translate.ts`; a logic layer spec renders with
  the real i18n of the test setup (English, reset before each test) and switches the language through the store.
- A story of a presentation that takes `t` wraps it in `withTranslate` (`client/.storybook/with-translate.tsx`); the
  Storybook toolbar language drives every story (`client/.storybook/preview.tsx`).

## The literal-text lint and its baseline

- Checked: text in JSX, in text attributes and props (`aria-label`, `alt`, `title`, `placeholder`, `label`, `*Label`,
  `*Text`, `*Title`, `*Message`, `*Description`) and in `toastError` / `toastSuccess`. Exempt: specs, stories, technical
  attributes, the field names and paths of a form (`*FieldPath(…)`, `get*FieldError(…)`), numbers and punctuation,
  CONSTANT_CASE, the brand.
- `client/linter/rules/literal-text-baseline.ts` lists the files written before the interface was translated. A file
  that is translated leaves the list in the same change; a file never joins it.
- Not checked: text in plain objects and functions outside JSX — confirm dialog options, validation messages of entity
  models. These go through `t` as well (a validator returns a code); the review catches them.

## Enforcement

| Rule | Checked by |
|---|---|
| Every key used in code is in every dictionary; every key of a dictionary is used; no empty translation | `npm run client:lint` · `client/i18next.config.ts` |
| A key exists in the English dictionary; every dictionary has the shape of the English one | `npm run client:build` · `client/src/app/i18n/dictionaries.ts` |
| No literal text in JSX, text attributes or toasts outside the baseline | `npm run client:lint` · ESLint `i18next/no-literal-string` · ESLint `toast-text/no-literal` · `client/linter/rules/literal-text-rule.ts` |
| i18next only inside `shared` | `npm run client:lint` · ESLint `no-restricted-imports` · `client/linter/rules/fsd-imports-rule.ts` |
| A presentation takes `t` as a prop, never calls `useT` | `npm run client:lint` · ESLint `no-restricted-syntax` · `client/linter/rules/ui-segment-rule.ts` |
| The language is detected once and kept on the device | `npm run client:test:unit` · `client/src/shared/lib/i18n/specs/language-store.spec.unit.ts` |
| `shared/ui` takes strings, never `t`, and gives no text prop a default; static keys | ❌ review |
| Dates through `formatDate` with the chosen language, no fixed locale | ❌ review |
| A sentence with markup is one key rendered by `Trans`; an error on screen kept as a code or the error | ❌ review |
| Text outside JSX (dialog options, validation messages) through `t` | ❌ review |
| The baseline only shrinks | ❌ review |
